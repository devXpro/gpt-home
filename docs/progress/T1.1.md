# T1.1 progress — pluginkit and plugin host

## pluginkit ready

`github.com/devXpro/gpt-home/pluginkit` compiles, is tested (`go test -race ./pluginkit/...`) and lint-clean.
The exported API is exactly §5.2, plus constants for the protocol keys:
`MetaAudience`, `MetaTimeout`, `MetaRole`, `MetaCaller`, `MetaVia` and `EnvPluginID`, `EnvDataDir`, `EnvLogLevel`,
`EnvHubVersion`.

Notes for plugin authors (T1.4):
- `New` panics on an id that breaks `^[a-z][a-z0-9]{1,15}$` (like `mcp.AddTool` panics on bad tools).
- `New` sets the server logger to stderr at `GPT_HOME_LOG_LEVEL` (default info).
- `Timeout` stores whole seconds, rounded up (an int in `_meta`).
- `Serve` returns nil on ctx cancellation and on stdin EOF (and does not log the SDK's "server run cancelled" error).
- `DataDir` creates the directory (0700) and returns an absolute path.
- Example plugin: `pluginkit/example` (`echo_say` assistant, `echo_list` inventory, `echo_reset` admin + 3 min timeout).

## Decisions
- go-sdk v1.8.0 client and server negotiate protocol 2026-07-28 (server/discover + subscriptions/listen); list_changed
  works there and on the legacy 2025-11-25 handshake (tested).
- A down plugin keeps its last known tools in the snapshot; calls return ErrPluginDown (503), and crashes do not churn
  the assistants' tool list. Changed fires only when the tools or instructions really differ.
- Unknown `gpt-home/audience` values are treated as admin (fail closed). A second inventory tool, or one without
  readOnlyHint, is ignored with a warning. Timeouts > 300 s are capped; bad ones fall back to 30 s.
- A run up for 60 s resets backoff and the failing state; failing retries every 5 min.
- Plugins run in their own process group (Setpgid) so a terminal Ctrl-C reaches only homed.
- Annotations are re-marshalled from go-sdk's struct, so `readOnlyHint`/`idempotentHint` are always present
  (false when absent) — semantically the same as the plugin's.
