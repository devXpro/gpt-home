## Decisions
- homed.yaml keeps listen, setup_listen and relay. After the one-time import the phase 1 sections move to
  homed.yaml.phase1 (never overwritten), so a stale hand edit cannot look applied and a deleted homed.db cannot bring
  revoked keys back.
- Relay changes apply at run time (no restart): relay manager restarts the frp client; Host guard, RP and the admin's
  CSRF origin read the current domain per request. Self-check runs at connect, then every 30 s.
- CLI: one code path over the admin API; when homed is stopped the same socket routes are served in-process (holding
  the instance lock), so admin/relay connect/key/plugin commands work offline; tool and relay status need homed.
- `key new` defaults to the owner; `--name/--plugins` are gone (person edits are P3 endpoints). Key ids are `k_…`
  (revoke by id or a unique start of ≥ 6 chars). `plugin remove` keeps data unless `--delete-data`.
- Tool calls from the CLI run as the owner (name in the audit), not "admin"; the CLI polls the call to show progress.
- Installer: a GitHub install learns the plugin id first and refuses an installed id before unpacking (the installer
  would otherwise replace and then delete the installed version's dir on the failed start). Hub update: job ends,
  1 s later graceful shutdown, exit 75.
- First-run page: starts only while no owner has a passkey; a busy port is logged, not fatal; it closes 2 min after
  the owner registered. Dev mode keeps it (PIN step) but refuses relay codes (409).
- Socket: peer uid must equal homed's (LOCAL_PEERCRED / SO_PEERCRED; other OSes rely on 0600).
- Keys' LastUsedAt stored at most once a minute per key (resolver wrapper).
