## Homebrew

The formula `Formula/gpt-home.rb` lives in the gpt-home repo itself and is committed to `main` by the release workflow
with `GITHUB_TOKEN` (no PAT, no `homebrew-tap` repo):

```sh
brew tap devxpro/gpt-home https://github.com/devXpro/gpt-home
brew install gpt-home          # installs `homed`
brew services start gpt-home   # LaunchAgent: run at login, KeepAlive, logs in $(brew --prefix)/var/log/gpt-home/homed.log
```

## Dockerfile contract (for T4.1's `Dockerfile` in the repo root)

GoReleaser (`dockers_v2`) does not compile in the image: it builds a context with the finished binaries and runs
`docker buildx build` over it. The context holds `Dockerfile`, `LICENSE` and `<os>/<arch>[/<variant>]/homed`
(`linux/amd64/homed`, `linux/arm64/homed`, `linux/arm/v7/homed`). So the Dockerfile must be a "copy the binary" one:

```dockerfile
FROM alpine:3.22            # or any multi-arch base
ARG TARGETPLATFORM          # linux/amd64, linux/arm64, linux/arm/v7
COPY $TARGETPLATFORM/homed /usr/local/bin/homed
ENTRYPOINT ["/usr/local/bin/homed"]
CMD ["run"]
```

No source build stage (the repo is not in the context). Verified with a throwaway Dockerfile of exactly this shape:
the three images build and `docker run <image> version` prints `homed <version>` on arm64 and armv7. The config is
`dockers_v2` id `homed` in `.goreleaser.yaml`; change `dockerfile:` there if the file gets another name. If T4.1's file
is a multi-stage source build, either rewrite it to the shape above or tell the orchestrator.

## How it is wired

- `.goreleaser.yaml` (v2.20): before hook `make web`; build `homed` (`./cmd/homed`, CGO off, `-trimpath`, ldflags
  `-s -w -X main.version={{.Version}} -X main.commit={{.ShortCommit}}`, darwin amd64/arm64, linux amd64/arm64/armv7);
  archives, `checksums.txt` (sha256, includes the Site bundle), changelog from commits (docs/test/ci/chore filtered),
  release (`prerelease: auto`, install footer), `brews`, `dockers_v2`.
- `.github/workflows/release.yml` on tag `v*`: checkout (full history), setup-go (go.mod), setup-node 22, Site bundle
  (`npm --prefix site ci`, `npm run check`, `npm run build`, `tar -C site -czf bin/gpt-home-site.tar.gz dist`; checked
  for `dist/.openai/hosting.json` and `dist/server/index.js`), qemu + buildx, ghcr login with `GITHUB_TOKEN`,
  `goreleaser release --clean`. Permissions: `contents: write`, `packages: write`.
- Site bundle: `gpt-home-site_<version>.tar.gz`, root `dist/`. A public bundle needs no merge of the real
  `.openai/hosting.json` (that one carries a person's project id): the build writes a clean one into `dist/.openai/`.
- Homebrew: `brews` is deprecated since GoReleaser 2.10 (it prints a warning; `goreleaser check` therefore exits 1,
  `release` works), the replacement `homebrew_casks` cannot carry a `service` block, and brew services is required, so
  the formula stays. It is a formula for macOS and Linux (armv7 included), `service do` = `run [opt_bin/"homed",
  "run"]`, `keep_alive true`, `restart_delay 10` (ThrottleInterval), logs in `var/log/gpt-home/homed.log`; the same
  settings as the LaunchAgent in docs/DEV.md. Committed to `main` as `github-actions[bot]` via the contents API.
  Skipped for pre-release tags.
- Hub self-update on a brew install: homed resolves the symlink and replaces the file in the Cellar; a later
  `brew upgrade` restores the brew version. Use one of the two ways.

## gpt-tv

Files in `/Users/devxpro/projects/family/gpt-tv`: `.goreleaser.yaml`, `.github/workflows/release.yml`,
`gpt-home-plugin.json` (id `tv`, title `TV`, binary `gpt-tv`, args `["serve"]`, minHubVersion `0.1.0`, homepage
`https://github.com/devXpro/gpt-tv`; uploaded to the release as an asset).

Build dependency: `go.mod` has `replace github.com/devXpro/gpt-home => ../gpt-home`. The release workflow checks gpt-home
out as a sibling (`path: gpt-home`, ref = repository variable `GPT_HOME_REF`, default `main`) and runs
GoReleaser with `workdir: gpt-tv`. Trade-off: the sibling checkout works today without a gpt-home tag but the build is
only reproducible if `GPT_HOME_REF` is pinned (set it to `v0.1.0` when releasing gpt-tv). The clean solution is to drop
the `replace` and require the tagged gpt-home (`go get github.com/devXpro/gpt-home@v0.1.0`), after which the second
checkout goes away; that touches gpt-tv's go.mod (not mine) so it is left as a follow-up for after v0.1.0. gpt-home must
be public for the checkout to work with the default token.
