## Decisions (for the people who consume the store)
- `store.Open(ctx, path) (*DB, error)`; `*DB` implements `Store`. WAL, foreign_keys, busy_timeout 10 s,
  `_txlock=immediate` (every transaction takes the write lock at BEGIN, so read-then-write cannot hit SQLITE_BUSY).
  Pool of at most 8 connections. The file and its `-wal`/`-shm` are 0600; a looser existing file is chmod-ed.
- Times are Unix ms (INTEGER), 0 = zero time. Create sets CreatedAt/UpdatedAt/InstalledAt when zero; Update-style
  methods always set UpdatedAt to now. Times come back in UTC with ms precision.
- Callers supply public ids: `store.NewID("s"|"k"|"i"|"cn")` gives `s_…` style ids; `store.NewUserHandle()` gives the 32
  random bytes of `Person.UserHandle`. An empty id is an error.
- Single-row mutators (Update, Delete, Rename, Touch, RecordUse, SetStepUp, Revoke) return `ErrNotFound` for a missing
  row. A Create that names a missing person (foreign key) returns `ErrNotFound` too.
- `Passkeys.Delete` is one SQL statement with the "person keeps another passkey" check inside: atomic without a
  transaction. `Invites.Consume` is one `UPDATE … RETURNING`: exactly one concurrent caller wins; the loser gets
  `ErrTokenUsed` / `ErrTokenExpired` / `ErrNotFound`. An invite is usable while `now < ExpiresAt`.
- `Invites.Revoke` on an already used invite is a no-op that keeps the first time. `PersonID == ""` is stored as NULL.
- `DeleteExpired` / `Prune` with a zero bound delete nothing. Audit ids are AUTOINCREMENT: never reused after Prune.
- Cascade: deleting a person removes passkeys, sessions, keys, invites and connections (FK). Sessions keep a plain
  `passkey_id` (no FK) and audit keeps `person_id`/`person` as text, so they survive. `keys.connection_id` and
  `connections.key_id` are plain text, no circular FK: the caller revokes the key first, as the contract says.
- The key table is called `person_keys` (`keys` is fine too, but this reads better in SQL).
- `Settings.Get` returns `HomeSettings{Language: "ru"}` until the first Put; Put stores what it is given.
- `(*DB).ImportPhase1(ctx, Phase1Import) (ImportResult, error)`: plain Go values, no YAML. One transaction; the marker
  `phase1_import` in the `meta` table makes it once per database. First person becomes the owner unless an owner already
  exists; existing ids/hashes are skipped (an existing person still gets their keys); an existing home name is kept;
  an empty import sets no marker; invalid ids or hashes fail the whole import. Imported plugins are `local`, enabled.
  Imported keys have an empty Hint. T2.6 builds `Phase1Import` from `internal/config` and calls it on start.
- Settings written by the import: only `HomeName` (Language stays the default "ru").
